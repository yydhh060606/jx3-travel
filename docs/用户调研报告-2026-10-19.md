## 一、摘要（先看这一段）

十二条反馈可以归为五个问题，其中**三条属于"事实错误"，必须立刻改**，与体验无关：

1. **门派心法写错了**：丐帮被标成「铁卫」（实际只有输出心法「笑尘诀」）、明教被标成单一「输出」（实际有 T 心法「明尊琉璃体」+ 输出「焚影圣诀」）。根因是数据结构只支持**一个 role**，无法表达双心法。
2. **蓬莱的地理挂错了**：现在把「蓬莱」门派挂在**山东泰安·泰山**，文案还写着「蓬莱为山东海上仙山」。剑网3 的蓬莱是**东海蓬莱岛**（虚构仙山），与山东蓬莱阁不是一回事。
3. **「同门留言」这个词用错了**：留言是全门派可见的，叫「同门」让用户以为只能同派交流；两位测试者分别提出改成「侠客」「侠士留言」。

另外三条是明确的功能缺口：**BGM**、**已行标签不够醒目**、**路线要告诉人怎么去**。最大的一块是**账号与公共留言**——它是本次唯一需要后端的需求，其他都能在前端做完。

## 三、问题归类

### A. 内容准确性（信任问题，最优先）

站点定位是"给剑网3 玩家看的旅行图鉴"，受众对门派设定极其敏感，写错一个心法就会失去可信度。

已在数据里核实到的具体错误：

| 门派 | 现状（`assets/data.js` → `SCHOOLS`）                | 应为                           | 说明                     |
| -- | ----------------------------------------------- | ---------------------------- | ---------------------- |
| 丐帮 | `role: '铁卫'`                                    | 输出（笑尘诀）                      | 丐帮在游戏内只有输出心法           |
| 明教 | `role: '输出'`                                    | 双心法：铁卫（明尊琉璃体）+ 输出（焚影圣诀）      | 单值字段无法表达               |
| 蓬莱 | 去处 `taian`（山东泰安·泰山）`school: '蓬莱'`，文案「蓬莱为山东海上仙山」 | 蓬莱门派位于**东海蓬莱岛**（虚构），与山东蓬莱阁无关 | 需重新选一个"东海"意象的真实去处，或改叙事 |

同一批数据里还有 20 个门派的定位需要复核（当前分布：输出 11 / 治疗 5 / 铁卫 4），建议以官方心法表为准逐条核对一遍。

**根因**：`SCHOOLS` 的 `role` 是**单值字符串**，天然表达不了"双心法"。改数据模型比改一条文案更重要。

### B. 信息架构与用词

「同门留言」是从"门派同好"的角度命名的，但功能上**所有人的留言都在一起**。三个人同时指出这一点，说明进入留言板后心理预期落空。

命名候选（按推荐度）：

| 方案              | 理由                   | 风险            |
| --------------- | -------------------- | ------------- |
| **侠客留言 / 侠客行纪** | 与"游记"气质一致，不限门派，玩家通用语 | 与站名"江湖行纪"有重复感 |
| **侠士留言**        | 同上，更书面               | 略生硬           |
| 江湖客话（当前留言板页内标题） | 气质最好                 | 太文，入口处不够直白    |

建议：**入口与计数统一叫「侠客留言」，页内标题保留「江湖客话」**——入口求明确，页内留文气。

### C. 功能缺口

| 需求        | 用户原话指向               | 现状                             |
| --------- | -------------------- | ------------------------------ |
| BGM       | "点进主页可以加一点 bgm"      | 完全没有声音层                        |
| 已行标签      | "点已行的加个标签"           | 有，但只是卡片右上角 30×30 的小印章，弱到需要凑近看  |
| 路线交通      | "咋去什么的！打车或者公共交通！"    | 行程只有"每天去哪、住哪"，没有"怎么到、要多久、花多少钱" |
| 登录 + 公共留言 | "id 和门派""大家留言可以互相看见" | 纯 localStorage，只能自己看见，换设备即失    |

### D. 视觉与氛围

- 字体"不好看、要醒目"：标题目前是马善政毛笔体（`MaShanZheng`），笔画细、辨识度低，在 1440 宽的屏幕上偏弱。
- 关于"醒目一点"要注意方向：**标题可以更重，正文不能跟着变重**，否则整页会吵。

## 五、逐项建议方案

### 5.1 心法体系：从单值到多值

数据模型改成数组，兼容旧数据：

```js
丐帮: { color: '#8a6d3b', roles: ['输出'], chi: ['笑尘诀'], tag: '…' },
明教: { color: '#e8722b', roles: ['铁卫', '输出'], chi: ['明尊琉璃体', '焚影圣诀'], tag: '…' },
```

- 卡片：定位标签显示 `铁卫 / 输出`（多值时并列，不写"双心法"三个字）
- 弹层：加一行「心法」，列出心法名
- 筛选：`role` 单选筛选要能命中"包含该定位"的门派
- 保留 `role` 字段做兼容，读取时 `role = roles[0]`

### 5.2 已行标签

现在是 30×30、字号 10.5px 的小印章，符合"克制"，但不符合用户"我一眼要看到哪些去过了"的诉求。

建议三档强化（择一或叠加）：

1. **印章放大到 46×46**，`rotate(-6deg)` 保持手写感，落在图片右下（避开右上角门派签）
2. 卡片图加一条**顶部朱线**（`border-top: 3px solid var(--seal)`），列表滑动时成排可见
3. 详情页顶部加**状态条**：「已于 2026-10-18 落印 · 重游」

> 注意：印章不能直接放大到 60px 以上，会压住实景主体；46 是"醒目但不喧宾夺主"的临界。

### 5.3 路线补交通

给 `ROUTES[].plan[].items` 之外新增结构化字段：

```js
{ d: '第二日', where: '西安 → 华阴', move: { mode: '高铁', time: '38 分', cost: '¥54.5', note: '西安北 → 华山北，站前有免费摆渡' } }
```

- 展示成一行小字：`🚄 高铁 38 分 · ¥54.5`（图标用 SVG，不用 emoji）
- 现成 9 条线路共约 30 段城际，需要人工核对车次；建议先填"方式 + 大致时长 + 大致票价"，不写死具体车次
- 城市内交通单独一段：「打车 15 分钟 / 公交 5 路直达」

### 5.4 标题字体

方向：换一款**更重、更清晰**的标题字，而不是继续加粗毛笔体。候选：思源宋体 Heavy（免费）、霞鹜文楷 Bold（免费）、站酷庆科黄油体（免费商用）。

- 建议：**标题用思源宋体 Heavy，副标题保留毛笔体**——一个稳重、一个文气，对比反而更强
- 字号与字重同步调：`font-weight: 900` + 略增字距，避免糊成一团
- 必须子集化后再自托管（现有 `_fonts/build_fonts.py` 可复用）

### 5.5 BGM

技术要点（不写会踩坑）：

- **必须由用户手势触发**：浏览器禁止自动播放，只能在"拆封信封"这一下开始播放，正好与叙事一致
- 默认**关**，首屏给一个右下角小开关（喇叭图标 + "乐"字），状态记忆在 localStorage
- 音量淡入 2 秒，切到后台自动暂停（`visibilitychange`）
- `prefers-reduced-motion: reduce` 不自动播放
- 版权：必须用可商用/可免费传播的曲目（如网易云/QQ 音乐无权直接引用），建议用 CC0 古风素材或自录

### 5.6 登录 + 公共留言（唯一需要后端的模块）

现状：`localStorage` 三把键（`jx3.comments.v1` / `jx3.likes.v1` / `jx3.journey.v1`），只有本机可见。

目标：ID + 门派登录，所有人可见彼此留言。

建议方案（按成本从低到高）：

| 方案       | 做法                            | 成本         | 适合            |
| -------- | ----------------------------- | ---------- | ------------- |
| A. 托管数据库 | 前端直连云数据库（匿名登录 + 行级权限），无需自建服务器 | 1–2 天      | **推荐**        |
| B. 自建轻后端 | Node/Go 写 REST，部署到同一域         | 3–5 天 + 运维 | 后续要举报/审核      |
| C. 第三方评论 | 接 Giscus / Waline 之类          | 1 天        | 但登录态与门派字段要额外做 |

产品设计要点：

- **登录不设密码**：ID（昵称）+ 门派即可，用设备 token 记住身份，降低门槛；后端存 `device_id` 做归属
- **门派只用于展示与筛选**，不做权限隔离（否则又会回到"同门"的坑）
- 留言保留现有的「赞 / 删」，删只允许删自己的（服务端校验 `device_id`）
- **必须有的治理**：敏感词过滤、举报入口、作者删除、异常频率限制
- 合规提醒：引入用户生成内容后，页面需要「用户协议 / 隐私说明」入口；不要采集手机号、微信等个人信息

数据表建议：

```sql
profiles(id, display_id, school, device_id, created_at)
comments(id, dest_id, author_id, text, created_at, status)
likes(comment_id, author_id)  -- 唯一索引防重复
```

## 九、V1.1 实施记录（2026-10-19 当日落地）

按第四节优先级，P0 三条与 P1 两条已改完，P2 的双心法 UI 随 P0 一起做了。

### 9.1 P0 · 心法从单值改多值

`assets/data.js` 的 `SCHOOLS` 去掉 `role`，改为 `chi: [[心法名, 定位], …]`（**主修在前**），
定位由心法反推，不再两处各写一遍：

```js
天策: chi: [['铁牢律', '铁卫'], ['傲血战意', '输出']]
明教: chi: [['焚影圣诀', '输出'], ['明尊琉璃体', '铁卫']]
丐帮: chi: [['笑尘诀', '输出']]        // 原为「铁卫」，已修正
```

- 20 个门派逐个对照官方心法表核过，共 32 门心法；单心法 11 家（明教、天策等 9 家为双心法）
- 卡片标签、弹层、筛选三处联动：`ROLE_OF()` 给主定位，`ROLES_OF()` 给全部定位
- 卡片小签显示「铁卫·输出」这类并列写法，`title` 里给出「心法：焚影圣诀（输出）· 明尊琉璃体（铁卫）」
- 弹层新增「门派心法」一栏，逐条列心法与定位；筛选按"能担任的定位"命中
- 计数变化：定位筛选角标从 输出 11 / 治疗 5 / 铁卫 4 变为 **输出 20 / 治疗 5 / 铁卫 4**
  （选「输出」出现 20 家是对的——每个门派都有 DPS 心法）

### 9.2 P0 · 蓬莱归位（三处轮换）

蓬莱门派在**东海蓬莱岛**，与山东登州蓬莱阁无关。为不动"20 处 × 20 门派"的一对一结构，
把三处去处与门派整体轮换，各自的城与诗跟着门派走：

| 去处 | 原门派 | 现门派 | 理由 |
| --- | --- | --- | --- |
| 舟山 · 东海普陀 | 刀宗 | **蓬莱** | 千岛浮海、潮声不歇，是"海上仙山"最近的实景；文案点明「并非山东登州的蓬莱城」 |
| 泰安 · 泰山 | 蓬莱 | **万灵山庄** | 五岳之尊，古松、碑碣、赤鳞鱼与满山生灵，"试以稚心问万灵"的一问 |
| 桂林 · 漓江 | 万灵山庄 | **刀宗** | 喀斯特孤峰拔地、锋棱分明，漓江烟雨终年不散，正合「断雨穿风」「孤锋」 |

三处的 `verse / blurb / origin / mark` 与三条种子留言的门派归属同步改掉。

### 9.3 P0 · 「同门留言」→「侠客留言」

全站 7 处：视图按钮（含计数）、页脚入口、留言板副标题、详情弹层留言区小标题、
`index.html` 注释、`app.js` 注释、`style.css` 注释。页内大标题仍留「江湖客话」，
入口求明确、页内留文气。

### 9.4 P1 · 已行标签强化

## 十、V1.2 实施记录：声音与云端留言（2026-10-19 下午）

本轮做的是报告第 5.5 节（BGM）与 5.6 节（登录 + 公共留言）——即此前挂着的两个待拍板项。

### 10.1 声音：素材全部自制

没有采用「找一段 CC0 古风曲子」的路线。原因有三：免费曲库的古风素材同质化严重、
署名条款各不相同、几十兆的曲子也不适合放在静态站。改为用 Python 合成：

- **古筝**：Karplus-Strong 弦模型（噪声激励 + 梳状拨弦位置 + 周期阻尼），
  衰减按「-60 dB / 目标余音」反推，所以低音不糊、高音不干
- **箫**：基音 + 强弱分明的二三次谐波 + 4.7 Hz 慢颤音 + 气声噪声，起音 100 ms
- **碰铃**：四个不谐和分音（1 / 2.76 / 5.40 / 8.93 倍）
- **混响**：合成脉冲响应（指数衰减噪声 + 四个早期反射）做卷积
- **无缝循环**：多渲染 4 秒尾巴，再折叠回开头叠加；实测接缝 |Δ| = 0.0067，
  小于相邻样本平均差值 0.0084，接缝处听不出接缝

编曲是 D 宫五声（D E F# A B），60 BPM，16 小节 64 秒，四句一换气：
第 5 / 13 小节进箫，第 9 小节前一拍加一次刮奏。每小节的 RMS 做了平衡，
最静与最响相差 10.4 dB——是乐句起伏，不是忽大忽小。

- 产物共 536 KB（bgm 500 KB + 四个音效 29 KB），BGM 只在首次手势后才开始下载
- 点击音效分四类：轻叩 / 翻页 / 落印 / 拆封，事件委托统一挂，55 ms 内同类不重复
- 导航右侧「音 / 静」开关，状态存 `jx3.sound.v1`；切后台暂停，回来接着放

### 10.2 登录：平台没有匿名登录，换成「落籍」

方案 A 原写的是「匿名登录 + device_id 归属」。接通云服务后确认：
**该平台的鉴权只有邮箱验证码、手机验证码、微信授权、WorkBuddy 账号、密码**，
匿名登录明确不在公开契约内。没有假装实现，改用等价的轻量身份方案：

> 名号（2–10 字）+ 门派（20 选 1）+ 32 位随机设备密钥，全部存在本机。
> 云端只收密钥的 SHA-256，用来判断「这条是不是你写的」。

- 首次发言自动弹入籍面板；落籍后表单里的名号与门派锁定，避免「卡片一个名、发言另一个名」
- 想升级成真账号，只需把 `device_hash` 的校验换成 `auth.uid()`，`cloud.js` 之外不用动
- 名号与门派在留言、弹层、留言板三处共用同一份身份

### 10.3 公共留言：三张表 + 六个函数

前端拿不到表——RLS 打开且**不建任何策略**，只有 `SECURITY DEFINER` 函数能读写：

| 函数 | 职责 |
| --- | --- |
| `jx3_list_comments` | 公开读，返回 `mine` / `liked` |
| `jx3_add_comment` | 校验长度、敏感词、20 秒一条、每天 30 条 |
| `jx3_del_comment` | 比对密钥哈希，只删自己的 |
| `jx3_toggle_like` | 赞 / 取消，按设备去重 |
| `jx3_report_comment` | 举报，满 4 条自动隐藏 |

原来 27 条种子留言迁到了云端（`created_at` 沿用原日期），留言板一上线就是满的。

### 10.4 一个绕不过去的域限制

云服务按 Origin 精确放行。实测：

```
Origin: https://jx3-travel.app.workbuddy.host   → 200
Origin: https://yydhh060606.github.io           → 403 access_denied
Origin: http://localhost:8080                   → 200
```

所以登录只在 WorkBuddy 发布的域名下可用。处理方式：

- 主站改为 <https://jx3-travel.app.workbuddy.host/>（已发布，云登录可用）
- GitHub Pages 保留为镜像；打开后留言区会显式说明「云端没连上，只显示本机留言」，
  并给出主站链接——不做静默降级
- SDK 自托管：jsdelivr 在本机与国内都不稳定，`assets/vendor/workbuddy-cloud.js` 直接放本地

### 11.2 楼中楼与 @ 提醒

数据层加了三列 + 一个函数（`jx3_comments.parent_id / reply_to / mentions`，`jx3_mentions_me`）。
几处刻意的取舍：

- **只排两层**。回「回复」也挂在同一楼里，用「回 某某」交代对象。三层以上缩进在 390px 宽度下不可读
- **父留言删掉不连带删回复**：外键 `ON DELETE SET NULL`，楼内回复升为顶层，别人的话不会因为楼层被删而消失
- **回复自动继承去处**：服务端从父留言取 `dest_id`，前端传的 `p_dest` 被忽略，
  这样不会出现「在 A 处回了一句，却挂到 B 处」的错位
- **@ 存名号而非 ID**：平台没有真账号，名号本身就是身份。代价是「半盏」与「半盏灯」会被同时命中，
  已在 README 写明；要根治得先有唯一 ID，与「真账号」是同一件事
- **未读时间点存本机**（`jx3.mentions.seen`）：换设备重新算，与服务端不存已读状态的做法一致
